## ── PROJECT CONTEXT ──

RHEO is a local-first, privacy-first desktop app. The landing page's chosen
creative direction is **"The Loom"**: RHEO's subsystems are threads on one loom,
and its AI is the shuttle running through all of them. The whole design rests on
**one rule that matters more than any individual visual**: reuse a single motif
(thread / stitching / patches) everywhere, rather than introducing new unrelated
visual languages per section. If you add anything that doesn't read as "made of
thread," you're breaking the thing that makes this design work. When in doubt,
ask before inventing a new visual system.

## ── THE AUTHORITATIVE VISUAL HIERARCHY (revised per round-2 feedback) ──

This corrects a mismatch that came up: the SVG loom animation was never the
problem, and it is NOT being replaced. The complaint that started this mascot
work was "the threads have no character," not "there's no animation." The fix is
small character accents added to what already exists, not a swap to static images
as the page's main visual.

Concretely (read BEFORE Task 2 and 3):

1. **The SVG loom stays exactly as built** — same 7 warp threads, same weft weave,
   same scroll-scrubbed reveal. This is still the hero. Nothing about it is being
   replaced.

2. **In the hero, there are NO per-thread icons and NO per-thread labels.**
   Hero's only job is the metaphor, not individuation. The original mistake was
   putting icons in Hero — it half-explained things an opening shot shouldn't be
   explaining yet, and duplicated what Threads and ModuleStore already do properly.
   Think of Hero as "a small patch pinned near a thread" NOT "a large illustration
   taking over the frame."

3. **In the Threads beat, each mascot `<img>` is introduced during the per-thread
   sequence.** This is WHERE the icon and label first appear together, paired.
   When a thread's `.is-active` class is added, fade its mascot in at that same
   moment, positioned above its label using the same percentage-based math used in
   `positionCaptions()` (`(w.x / W) * 100`). This is the thread's one-time
   introduction — not a hero-load animation.

4. **In the module-store section (Task 3), mascots ARE the primary card visual.**
   That section never had SVG thread lines to begin with, so there's nothing for it
   to coexist with — a patch-card grid with the illustrated PNG as each card's icon
   is correct there specifically.

**Full page flow, top to bottom, after this work is done:**
Header (sticky, unchanged) →
  Hero (SVG weave draws in; headline; NO per-thread icons or labels here at all —
    Hero's only job is the metaphor, not individuation) →
  Threads beat (each thread highlighted in turn — THIS is where its icon and label
    appear together, for the first time, paired — this is the thread's introduction) →
  Shuttle beat (unchanged 3 AI captions; optionally show the relevant mascot inside
    the caption box next to its tag label — nice-to-have) →
  Fabric beat (unchanged zoom-out; no mascots here, it's about the whole fabric,
    not one subsystem) →
  **NEW, non-pinned** module-store section (12 patch cards, mascot + label +
    one-line description each — the full explained reference) →
  Closing CTA (unchanged)

**Why this changed:** three sections were all doing "show the feature list" with no
distinct purpose between them — that's the actual complaint, not a visual quality
problem. Each section now has exactly one job:
  - Hero = feel the metaphor
  - Threads = meet each thread once
  - ModuleStore = the full reference

Putting icons in Hero was the original mistake; it half-explained things an opening
shot shouldn't be explaining yet, and duplicated what Threads and ModuleStore already
do properly.

**Numbered files:** if the generated assets came out as `1.png`–`12.png` instead of
the `mascot-<slug>.png` convention, they're in the exact order the prompts were listed
in `rheo-mascot-image-prompts.md`:
  `1`=Time/Focus, `2`=Money, `3`=Learning, `4`=Chat, `5`=Terminal, `6`=Timeline,
  `7`=Goals, `8`=Life Phases, `9`=Agent Orchestration, `10`=Content Creation,
  `11`=External, `12`=Context Brain.
  `1`–`6` are the hero-thread accents; all 12 populate the module-store grid.
  Rename to the slug convention if cleaner in code, or use numbers directly with a
  comment mapping — either is fine, just pick one and be consistent.

**Where the module-store section physically sits:** it is NOT part of the pinned
`#scrollSpace` sequence — don't extend that timeline to fit it in. It's a normal,
non-pinned `<section>` inserted between `#scrollSpace` and `#closing`, with a simple
viewport-triggered fade-in stagger (native `animation-timeline: view()` CSS approach,
or a basic `ScrollTrigger` toggle — either is fine, this section doesn't need
scroll-scrubbing). This matches how `.closing` already behaves, and gives a calmer
pacing beat after four straight sections of choreographed motion in the hero.

## ── FILES THAT ALREADY EXIST ──

- **`rheo-loom-prototype-v2.html`** — the working scroll prototype. A pinned, GSAP
  `ScrollTrigger`-scrubbed sequence: Hero (weave draws in) → Threads (7 subsystems
  highlighted in turn) → Shuttle (AI captions on 3 of them) → Fabric (zoom-out payoff)
  → Closing CTA. Uses Lenis for smooth scroll, a custom `easeInOutCubic` ease registered
  via `gsap.registerEase`, and a two-layer SVG clip-path trick (`#clipOver` / `#clipUnder`)
  to fake the woven over/under look with one shared path.

- **`rheo-thread-patches.html`** — a reference sheet of 7 hand-coded SVG "patch" icons
  (one per core subsystem), styled as embroidered/stitched badges with a dashed border,
  sitting in `.patch` cards inside a `.grid`.

- **`rheo-mascot-image-prompts.md`** — the prompts used to generate 12 richer illustrated
  PNG mascots (superset of the 7 SVG patches) in an "embroidered patch" art style, via an
  external image generator. These are the images this task is about integrating.

## ── KNOWN BUGS (FIX THESE — ROUND 2 FEEDBACK FROM THE LIVE BUILD) ──

### Bug 1 — `.warp-label` text renders black on the `#09090b` background, effectively invisible
It should inherit `fill: var(--text-secondary)`. Since this was ported into `LoomSVG.tsx`,
check in this order rather than guessing:
  (a) did the `.warp-label` CSS rule survive the port into the component's
      stylesheet/module at all;
  (b) if using CSS Modules, did the original global selector stop matching after
      class-name hashing;
  (c) is a Tailwind utility or inline style overriding `fill` after the class applies;
  (d) is `--text-secondary` actually defined in whatever scope this component renders in.
Fix the root cause, not just the symptom color.

### Bug 2 — Only 4 of 7 Hero threads show an icon
Per the structural fix above, this bug is MOOT — Hero shouldn't have per-thread icons at
all. Remove them from Hero rather than debugging the count; move icon+label pairing to the
Threads beat instead (see the revised page flow above).

## ── TASKS ──

### Task 1 — Swap the patch sheet's icons
In `rheo-thread-patches.html`, replace each `.patch`'s inline SVG with
`<img src="assets/mascots/mascot-<slug>.png" alt="<LABEL> mascot patch">`, sized to fill
the same footprint the SVG currently does. Keep the `.patch` div's dashed border, background,
and mono label exactly as they are — only the icon changes. Add 6 new `.patch` entries for
the subsystems that aren't in this file yet (goals, life phases, agent orchestration, content
creation, external, context brain).

### Task 2 — Introduce each mascot during the Threads beat, NOT the Hero
Don't fade mascots in with the page-load stagger — that's the Hero beat, and Hero stays
metaphor-only, no per-thread icons (see Visual Hierarchy above). Instead, add each mascot
`<img>` into the same per-thread sequence that already highlights each `w.lineEl` in turn
during the Threads beat (the loop building the `tl.to(w.lineEl, {...})` calls). When a
thread's `.is-active` class is added, fade its mascot in at that same moment, positioned
above its label using the same percentage-based math already used in `positionCaptions()`
(`(w.x / W) * 100`). This is the thread's one-time introduction — icon and label appearing
together for the first time — not a hero-load animation.

### Task 3 — Give the other 6 subsystems a section
Goals, Life Phases, Agent Orchestration, Content Creation, External, and Context Brain aren't
threads in the hero — they need a home. Build this as the **module-store section** that was
already planned for this page (features framed as "spare threads you can add," a bento grid
with a border-beam hover effect), placed after the Fabric beat and before the Closing CTA. Use
all 12 mascots here (repeating the 6 hero ones is fine — reinforcement, not redundancy), each
as a small patch card: mascot image, label, one-line description. Match the exact
dashed-border/glass-card visual style already established in `rheo-thread-patches.html`'s
`.patch` class — don't design a new card style for this.

## ── CONSTRAINTS (NON-NEGOTIABLE, CARRIED OVER FROM EARLIER DESIGN DECISIONS) ──

- Dark mode only. No new colors outside the existing tokens
  (`--bg #09090b`, `--amber #fbbf24`, `--terracotta #c2703d`, `--text #fafafa`,
  `--text-secondary #a1a1aa`).
- Every new animation needs the same treatment as existing ones: driven by GSAP
  `ScrollTrigger` or the page-load stagger tween, using the registered `easeInOutCubic`,
  not a default ease.
- Respect `prefers-reduced-motion` the same way the rest of the file already does (see the
  `reduceMotion` branch near the top of the script) — new elements need a static end-state in
  that branch too, not just the animated path.
- Provide real `alt` text per mascot (use the subsystem label) — these are meaningful content,
  not decoration, so they're not `alt=""`.
- Don't add a second card style, a second icon style, or a second color for "new feature"
  sections. If it doesn't look like it's made of the same thread as everything else, it's
  wrong even if it looks good on its own.

## ── DONE MEANS ──

- All 12 mascots have a visible home somewhere on the page.
- The hero's 7 threads and the module-store grid visually agree with each other (same patch
  style, same palette).
- Missing image files don't break the page.
- Reduced-motion users get the same information, just without the animation.
