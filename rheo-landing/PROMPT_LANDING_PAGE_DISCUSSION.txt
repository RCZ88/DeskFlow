This is the round-2 corrected spec — read it carefully, it overrides my earlier
assumptions about where mascots go.

**The SVG loom stays exactly as built** — same 7 warp threads, same weft weave,
same scroll-scrubbed reveal. This is still the hero. Nothing about it is being
replaced. The complaint was "the threads have no character," not "there's no
animation."

**In the hero, there should be NO per-thread icons and NO per-thread labels.**
Hero's only job is the metaphor, not individuation. The original mistake was
putting icons in Hero — it half-explained things an opening shot shouldn't be
explaining yet, and duplicated what Threads and ModuleStore already do properly.

**In the Threads beat, each mascot <img> is introduced during the per-thread
sequence** — this is WHERE the icon and label first appear together, paired.
When a thread's `.is-active` class is added, fade its mascot in at that same
moment, positioned above its label using the same percentage-based math already
used in `positionCaptions()` (`(w.x / W) * 100`). This is the thread's one-time
introduction — not a hero-load animation.

**In the module-store section, mascots ARE the primary card visual.** That
section never had SVG thread lines to begin with, so there's nothing for it to
coexist with — a patch-card grid with the illustrated PNG as each card's icon is
correct there specifically.

**Full page flow, top to bottom, after this work is done (revised per round-2):**
Header → Hero (SVG weave draws in; headline; NO per-thread icons or labels) →
Threads beat (each thread highlighted in turn — THIS is where icon+label appear
together for the first time, paired) → Shuttle beat (unchanged 3 AI captions;
optionally show the relevant mascot inside the caption box) → Fabric beat
(unchanged zoom-out; no mascots) → NEW non-pinned module-store section (12 patch
cards, mascot + label + one-line description — the full explained reference) →
Closing CTA (unchanged).

**Why this changed:** three sections were all doing "show the feature list" with
no distinct purpose between them — that's the actual complaint. Each section now
has exactly one job:
  - Hero = feel the metaphor
  - Threads = meet each thread once
  - ModuleStore = the full reference

Putting icons in Hero was the original mistake; it half-explained things an
opening shot shouldn't be explaining yet, and duplicated what Threads and
ModuleStore already do properly.

**Design rules (non-negotiable):**
1. Dark mode only. No new colors outside the existing tokens.
2. Every animation uses GSAP ScrollTrigger or page-load stagger tween, with the
   registered easeInOutCubic. No default ease.
3. Respect prefers-reduced-motion — new elements need a static end-state in that
   branch too.
4. Real alt text per mascot (use the subsystem label) — not alt="".
5. Single motif everywhere: thread / stitching / patches. If it doesn't read as
   "made of thread," it's wrong even if it looks good on its own.
6. Don't add a second card style, a second icon style, or a second color for
   "new feature" sections.
7. The module-store section is NOT part of the pinned #scrollSpace sequence —
   don't extend that timeline to fit it. It's a normal, non-pinned <section>
   inserted between #scrollSpace and #closing, with a simple viewport-triggered
   fade-in stagger (native animation-timeline: view() CSS, or basic ScrollTrigger
   toggle). This matches how .closing already behaves.

**Done means:**
- All 12 mascots have a visible home somewhere on the page.
- The hero's 7 threads and the module-store grid visually agree (same patch
  style, same palette).
- Missing image files don't break the page.
- Reduced-motion users get the same information, just without the animation.
