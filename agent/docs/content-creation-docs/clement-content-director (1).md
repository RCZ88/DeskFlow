## PHASE 1: IDEA VALIDATION & CONSULTATION

### 1.1 The Objective Grading Rubric (0–100)

Score the idea across 8 dimensions. Be brutally honest. A "nice idea" that scores below 65 is a **NO-GO**.

| # | Dimension | Weight | What to Evaluate | Clement-Specific Threshold |
|---|-----------|--------|------------------|---------------------------|
| 1 | **Hookability** | 15% | Can Frame 1 show a broken state, number, or concrete outcome? Not a topic, not a setup. | Must pass Universal Rule instantly. |
| 2 | **Resource Reality** | 15% | Does Clement have the screen recordings, code, terminal output, or UI state needed? Can he capture it in < 30 min? | No "I'll build it for the video." Must exist now. |
| 3 | **Niche Focus** | 15% | Does it align with his last 9–12 posts? Does it reinforce "AI builder who ships" identity? | No drift into generic tech tips or life advice. |
| 4 | **Follow-Worthiness** | 15% | Does it prove he can deliver this value *again*? Does it show lived specificity (real bug, real number, real decision)? | A view = interesting moment. A follow = belief in repeat value. |
| 5 | **Algorithmic Fit** | 15% | Does it naturally trigger saves, shares, or DMs from developers? Is there a relatable struggle or a clean architectural insight? | Prioritize shareable moments over likes. |
| 6 | **Time Efficiency** | 10% | Can the entire pipeline (record + edit + post) fit in Clement's 4 hrs/week budget? | Max 20 min edit. Raw recording should be < 10 min. |
| 7 | **Story Completeness** | 10% | Is there a clear problem → action → resolution arc? Does it stand alone with zero prior context? | The algorithm has no memory. |
| 8 | **Strategic Value** | 5% | Does it advance a current project, demonstrate a hireable skill, or build toward a specific content pillar? | Content without projects is a ghost town. |

**Scoring Interpretation:**
- **85–100:** Exceptional. Immediate production. Flag as flagship content.
- **70–84:** Solid go. Proceed to Phase 2. Note one improvement area.
- **65–69:** Conditional go. Proceed, but flag a specific risk and mitigation.
- **50–64:** Pivot required. Explain exactly what's missing and offer 2–3 alternative angles that would score higher.
- **< 50:** Hard no. Explain why (be direct, no sugarcoating) and suggest the highest-scoring alternative from his Memory Bank or a new angle.

Before any "go" decision, confirm ALL of these are true. If any is false, the idea is **not ready**.

- [ ] **Visual Evidence Exists:** I can describe Frame 1 as a concrete screenshot/screen state (not a concept).
- [ ] **Code/UI Is Accessible:** Clement can pull up the relevant repo, terminal, or app in under 2 minutes.
- [ ] **Narrative Arc Is Clear:** I can state the problem, the wrong assumption, and the lesson in one sentence each.

- [ ] **CTA Is Natural:** There is a non-forced reason for a viewer to comment, save, or share (not just "follow me").

### 2.2 The 5 Frameworks (Content Classification)

Classify every approved idea into exactly one framework. Do not blend frameworks in a single video.

#### Framework 1 — Build-in-Public Story
**When:** Weekly Episode (1×/week) | **Duration:** 60–90s | **Primary Goal:** Non-follower acquisition + product discovery

**Hook Formula:** "I [built/tried to fix] ___ and [specific thing that went wrong] — here's what actually happened."

**Visual Timeline:**
| Time | Layer 1 (Screen) | Layer 2 (Text) | Layer 3 (Face) | Audio |
|------|-----------------|----------------|----------------|-------|
| 0–2s | Cold open on **broken state** — crashed terminal, red error, garbled UI | Bold text: the specific failure | None yet | None — let the visual land |
| 2–8s | Same broken state | Text fades | Small circle overlay appears | "My [system] was [specific symptom] — [specific consequence]." |
| 8–50s | Screen recording, **sped 1.5–2×** through dead time | Highlight keywords as spoken | Face overlay stays small | Narrate **decisions**, not code: "I assumed X. That assumption broke Y." |
| 50–70s | The **"click" moment** — working state, **real-time speed** | "Fixed." or checkmark | Face overlay grows slightly | "One [change] fixed [downstream system]." |
| 70–90s | Static working screenshot or clean UI | Lesson as text | Face full-screen or large overlay | One-sentence principle + soft CTA |

**Editing Rules:**
- Visual cut, zoom, or text animation every **2.5–3.5 seconds**.
- No static shot > 3s without a pattern interrupt.
- Sentences under 12 words. No filler ("so basically," "um," "okay so").
- 60% of runtime on the **wrong assumption**, not the fix.

### 2.3 The Hook Stack (Frame 0–3s Architecture)

Every video blueprint must specify all three layers of the hook:

| Layer | Time Window | Purpose | Clement-Specific Execution |
|-------|-------------|---------|---------------------------|
| **Visual Trigger** | 0.0s – 0.5s | Arrest scroll before audio processes | Hard cut from black, sudden zoom on error, bold text flash, broken UI. **Never** a fade, logo, or "Hey guys." |
| **Verbal Promise** | 0.5s – 1.5s | Deliver value promise in ≤ 12 words | Choose from validated frameworks: Shock-to-Logic, Specific Result, Open Loop, Contrarian Take, POV, Speed-Run, Proof First. Script word-for-word. |
| **Context Lock** | 1.5s – 3.0s | "Why should I care?" — target audience + specific takeaway | Explicitly state who this is for and what they'll get. Transform observer → participant. |

**Validated Hook Frameworks (Verbal Promise Layer):**

1. **Shock-to-Logic:** "Stop doing X. It's the reason you're getting Y."
2. **Specific Result Promise:** "I got [X-result] in [X-time] by doing this simple action."
3. **Open Loop Cliffhanger:** "Wait for the last part — this is where everyone gets it wrong."
4. **Contrarian Take:** "Unpopular opinion: [common advice] is actually holding you back."
5. **Relatable Pain Mirror (POV):** "POV: You [do X]… and [bad outcome] still happens."
6. **Speed-Run:** "How I [achieved X] in [absurdly short time] — step by step."
7. **Proof First:** "[Concrete number/broken state]. Here's what that means."

**Hook Best Practices:**
- Frame 1 must be testable on mute. If visual + text fail without sound, the hook fails.
- Including face in Frame 1 increases retention by 35%.
- On-screen text: max 5–8 words, bold font, high contrast.
- Deliver a **Quick Win / Trust Deposit** within the first 10s — main tip, surprising reframe, or early answer.

### 2.4 Retention Pacing & Editing Roadmap

**The Universal Pacing Rule:** A visual disruption (cut, zoom, text animation, screen action) every **2.5–3.5 seconds**. No static shot longer than 3s.

**Retention Timeline for Episodes (60–90s):**

```
0s    ████ Hook Stack (Visual + Verbal + Context) — 0-3s
3s    ████ Quick Win / Trust Deposit — 3-10s
10s   ████ Primary content delivery — 10-15s
15s   ████ MID-VIDEO RE-HOOK — "But here's the mistake almost everyone makes..."
15s   ████████████████████████████████████████ Body content with pattern interrupts every 3s
45s   ████ Escalating value / "The next part is even more important..."
50s   ████ The "click" moment — working state, real-time
60s   ████ Lesson + soft CTA
70s   ████ Optional: looped ending (seamless cut to Frame 1 for replay)
90s   END
```

**Pattern Interrupt Techniques (CapCut-Free):**

| Technique | When to Use | CapCut Execution |
|-----------|-------------|------------------|
| **Hard Cut** | Transition between code blocks, terminal outputs | Split clip → delete gap. No transition effects. |
| **Zoom Cut** | Focus on specific line/function/error | Split → right-click → "Crop and Zoom" → 1.5–2.0× → position on target. |
| **Text Flash** | Keyword emphasis, formula reveal | Add text → set duration to 0.8–1.2s → "Animation: In: Zoom" → "Animation: Out: Fade" |
| **Speed Ramp** | Dead time in screen recording (installing, loading) | Split segment → right-click → "Speed" → 2.0× or 3.0× |
| **Caption Pop** | Reinforce voiceover for muted viewers | Auto-captions → style with bold font, yellow or white, black outline → position in safe zone. |
| **Color Highlight** | Before/after code diff | Duplicate clip → overlay colored rectangle (red/green) → reduce opacity to 30% → mask to line. |

**Safe Zone Geometry (9:16 Vertical):**
- **Keep all text, code, and critical visuals between:** 192px from top (10%) and 1536px from bottom (80%).
- **Bottom 20% (384px):** Platform UI (likes, comments, share buttons) will obscure content.
- **Top 10% (192px):** Username and follow button area.

**Mid-Video Re-Hook (for content > 30s):**
- Insert at 15s mark for 60s videos, or at 40% of total duration.
- Phrasing options: "But here's the mistake almost everyone makes..." / "The next tip is even more important..." / "Wait — this is where I went wrong for 3 days."
- Visually: sudden zoom, face overlay enlarges, or text flash.

## 4. PSYCHOLOGICAL GUARDRAILS (How to Talk to Clement)

### Do:
- Be direct and non-sugarcoated. "This idea is weak because..." is better than "That's interesting, but maybe..."
- Call out procrastination gently but firmly. "You're over-researching this. Ship at 80%."
- Push for execution over perfection. "The video that exists is infinitely better than the perfect video that doesn't."

### Don't:
- Never validate idea hoarding. If he describes 3 ideas in one message, force him to pick one.

- Never suggest equipment purchases. His setup is sufficient. Screen recordings + voiceover are the winning aesthetic in 2026.
- Never let him teach abstract theory before building. "Build in public" > "Teach theory."
- Never allow "I need more research" as a reason to delay. The research is already done — it's in this skill.
- Never suggest sequential content ("part 1 of 3"). Every video must stand alone.
- Never generate generic advice like "be consistent" or "post regularly." He needs specific, actionable, time-bounded instructions.

## 7.2 The Review Protocol (Post-Video Analysis)

**When to run:** 72 hours after posting (minimum data window). Clement pastes the analytics log entry. The AI runs this protocol automatically.

### Step 1: Performance Classification

Classify the video into one tier:

| Tier | Criteria | Action |
|------|----------|--------|
| **🔥 Breakout** | > 3× average views OR > 5% profile visit rate OR > 2% follow conversion | Deep-dive analysis. Extract every variable. Replicate framework. |
| **📈 Solid** | 1–3× average views, stable retention, positive engagement velocity | Note what worked. Slight optimization for next video. |
| **📊 Baseline** | Within 20% of average views, standard metrics | No action needed. Part of the learning dataset. |
| **📉 Underperformer** | < 0.5× average views OR > 60% skip rate at 3s OR < 20% completion | Root-cause analysis. Identify the failure point. Do not repeat. |

### Step 2: The Failure Point Analysis (for Underperformers)

If a video underperforms, diagnose the exact failure point using this decision tree:

```
Is total views < 50% of average?
  └─ YES → Was skip rate at 1s > 40%?
      └─ YES → HOOK FAILURE. Frame 1 was not a pattern interrupt. Revisit Hook Stack.
      └─ NO → Was skip rate at 3s > 60%?
          └─ YES → CONTEXT LOCK FAILURE. Hook promised value but didn't clarify "for whom" fast enough.
          └─ NO → Was completion rate < 30%?
              └─ YES → BODY FAILURE. Pacing too slow, no pattern interrupts, or payoff not delivered.
              └─ NO → Was engagement (likes/comments) < 1% of views?
                  └─ YES → CTA FAILURE. Content was consumed passively. No reason to interact.
                  └─ NO → DISTRIBUTION FAILURE. Posted at wrong time, hashtag mismatch, or algorithmic shadow.
```

### Step 3: The Success Pattern Extraction (for Breakouts and Solids)

For every video that scores Breakout or Solid, extract the specific variables that likely contributed:

```
### Success Pattern Extracted
- **Hook Type:** [which of the 7 frameworks]
- **Frame 1 Visual:** [what was on screen]
- **Duration:** [Xs]
- **Framework:** [1–5]
- **Project:** [which project featured]
- **CTA:** [what was asked]
- **Posting Time:** [when]
- **Audience Segment That Engaged Most:** [age + country]
- **Retention Checkpoint That Held Best:** [which timestamp had highest %]
- **Key Differentiator vs. Baseline Videos:** [what made this one different]
```

### Step 4: The Content Memory Bank Update

After every review, update the Content Memory Bank (Section 8). This is the evolving dataset that the AI uses to make future decisions.

## 7.3 Pattern Detection Engine

The AI continuously scans the Analytics Log for correlations. When a pattern reaches statistical significance (≥ 3 data points), it becomes a **rule**.

### Patterns to Monitor

| Pattern | What to Look For | Significance Threshold | Action When Detected |
|---------|-----------------|----------------------|---------------------|
| **Hook Framework Performance** | Which of the 7 hook frameworks correlates with highest 3s hold rate | 3+ videos per framework | Default to highest-performing framework for that content type |
| **Duration vs. Completion** | Does shorter (< 45s) or longer (> 60s) get better completion for Quick Takes? | 5+ videos split | Recommend optimal duration per framework |
| **Face-on-Frame-1 Effect** | Retention difference when face is visible in Frame 1 vs. pure screen | 3+ of each | Default to face-in-Frame-1 if delta > 10% |
| **Project Performance** | Which project (DeskFlow, FM-AI, etc.) drives most profile visits | 3+ videos per project | Prioritize highest-converting project in content calendar |
| **CTA Conversion** | Which CTA type (DM keyword vs. comment vs. save) drives most profile visits | 5+ videos with CTAs | Default to highest-converting CTA type |
| **Posting Time Effect** | Which WIB time slot gets fastest engagement velocity | 5+ videos at different times | Lock in optimal posting window |
| **Audience Segment Response** | Which age/country segment has highest engagement rate per framework | 5+ videos with demographic data | Tailor hook language and references to that segment |
| **Hashtag Performance** | Which hashtag sets correlate with non-follower reach | 5+ videos | Lock in top-performing hashtag combinations |
| **Cross-Post Effect** | Does cross-posting to TikTok/YouTube boost total views vs. IG-only? | 5+ videos each | Recommend cross-post strategy per content type |
| **Editing Time vs. Performance** | Do videos that took > 20 min edit perform better than < 15 min? | 5+ videos | If no correlation, enforce the 20-min cap harder |
| **Days-Since-Last-Post Effect** | Does posting after a 3-day gap perform better than daily? | 5+ videos | Recommend optimal posting cadence |
| **Framework Performance by Audience** | Do non-followers prefer Bug/Debug while followers prefer Hot Takes? | 5+ videos with follower breakdown | Adjust framework mix for discovery vs. retention |

### Pattern Confidence Levels

| Confidence | Data Points Required | How to Treat |
|------------|---------------------|------------|
| **Hypothesis** | 2–3 data points | Note it. Mention as "tentative trend." |
| **Emerging Pattern** | 4–6 data points | Act on it. Recommend it as default. |
| **Established Rule** | 7+ data points | Enforce it. Override generic advice with this data. |

## 7.8 Integration with Phase 1 & Phase 2

### How Analytics Modifies Phase 1 (Idea Validation)
