## 3. The 5 Bugs — Requirements & Acceptance Criteria

### Fix 1 — Websites solar system renders BLANK (CRITICAL)
**Root cause (already diagnosed):** `GalaxyView` offsets the websites galaxy by x=3250, but `SolarSystemScene` renders the sun/planets at x=0. Entering a websites solar system (galaxy sphere → "Enter Solar System" → `handleEnterSystem`; or category dropdown → `handleCategorySelect`) animates the camera to x=3250 → camera looks at empty space → blank.

**Requirement:**
- Render the solar-system scene at the same x-offset as the active galaxy (x=0 for apps, x=3250 for websites) so camera and scene always agree.
- Cover ALL entry paths consistently: `handleEnterSystem`, `handleCategorySelect`, `handlePlanetClick`/`handlePlanetPointerDown/Up`, `focusOnPlanet`, `handleZoomOut`, `resetCameraToGalaxy`, and the Canvas initial camera (line 4015). The offset must be applied either by wrapping `SolarSystemScene`'s content in an offset `<group>` or by offsetting the camera animation targets — choose the approach that cannot drift out of sync, and say why.
- `PlanetTracker` / `planetPositionsRef` / `OrbitControls target` must stay in the same coordinate space as the rendered planets.
- AC: entering a websites solar system ANY way shows sun + planets. Never blank.

### Fix 2 — Galaxy-view category labels huge, overlapping, detached
**Root cause:** `<Html center distanceFactor={30}>` scales the label ~7.5× at galaxy camera distance (~224 units) → giant chips covering neighboring systems.

**Requirement:**
- Category chips must render at constant, readable screen size regardless of zoom (no `distanceFactor`, or a corrected scale strategy — justify it).
- Chips must stay visually attached to their sphere (anchor above the sphere, clear leader/offset, no clipping by the galaxy dust).
- Add subtle polish consistent with DeskFlow glass design: small dot with the system's sun color + category name; keep `pointerEvents: 'none'`; avoid `backdrop-filter` (blurry in Electron); keep chips small enough that adjacent chips never overlap at default galaxy zoom.
- AC: at default galaxy view (camera ~224 units), all chips readable, on top of their spheres, no overlap.

### Fix 3 — Labels blurry; period switching leaves empty/broken view
**Root cause:** (a) `TexturedPlanet` label uses `cameraDist` React state updated every frame + `transform: scale(...)` + `backdropFilter: blur(8px)` → per-frame re-render and rasterization blur; (b) after a period switch, `currentCategory` may not exist in the new data → `planets = []` → only the sun renders.

**Requirement:**
- Planet labels: constant screen size, crisp at all distances; fade opacity by camera distance WITHOUT per-frame React state (e.g. a ref-driven DOM update or drei `Html`'s own distance handling — but no per-frame `setState`; no `backdropFilter`; no fractional-scale text).
- Hover still shows the duration tooltip and colored border (existing behavior, keep it).
- Period switch: if `currentCategory` no longer exists in the new period's systems, auto-select the first available system for the active galaxy (or fall back to galaxy view) — never render an empty solar system. Also handle the case where ALL systems are empty (show a friendly empty state instead of a lone sun — humancentred-UIUX: empty state with icon + one line + a "back to galaxy" action).
- AC: no blurry text; switching today/week/month/all never shows an empty/broken solar system; console free of errors.

### Fix 4 — Planets are very dark
**Root cause:** dim lighting (ambient 0.03, hemisphere 0.08, point light `decay 1.5` ≈ 0 at outer orbits), planet emissive pulse base only 0.15–0.35, `ACES_FILMIC` tone mapping darkening, dark procedural texture base (`#1e1e40`).

**Requirement:** Make planets clearly visible and saturated at ALL orbits in BOTH apps and websites solar systems, WITHOUT blowing out the sun:
- Specify the exact lighting set (ambient / hemisphere / directional / point intensities, distances, decays) with the math for why outer planets (orbit ~220) receive enough light.
- Specify planet material changes (e.g. raise `emissiveIntensity` pulse base; consider `toneMapped={false}` on planet materials, or a different `ToneMapping` mode / params — pick one and justify).
- Keep the bloom from washing planets (luminanceThreshold/radius adjustments if needed).
- Vignette must not crush planet brightness at the edges.
- AC: planets clearly lit at orbit 10 AND orbit 220; sun still the brightest object; before/after values documented in RESULT.md.

### Fix 5 — Graphics quality option (surface existing perfMode)
**Existing (hidden):** `perfMode: 'high' | 'balanced' | 'performance'` already gates: `dpr` cap (line 4028), Bloom/Vignette (4049/4059), particle counts 6000/2500/1000 (apps) and 5000/2000/800 (websites), and `PerformanceMonitor` auto-degrade (4031–4035). There is no UI and no persistence.

**Requirement:**
- A user-facing **Graphics Quality** control (Low / Medium / High — map onto performance / balanced / high) in the existing "Perf" panel (button at lines 3872–3881), following DeskFlow design (glass card, `rounded-xl` max, zinc tokens, lucide icon).
- Persist in localStorage (`deskflow-graphics-quality`, wrapped in try/catch — project invariant), applied on mount.
- Optionally tie MSAA on: the canvas has `antialias: false` + `multisampling={0}`; document whether enabling MSAA on High is worth the cost in Electron and if so specify the exact change.
- AC: picking a quality level changes dpr/particles/bloom immediately and survives restart; the Perf panel still shows FPS.
