**Goal:** Eliminate the 3 conflicting Goal/LongTermGoal type definitions and establish ONE canonical type.

**Implementation:**

   - `GoalStatus` — 'active' | 'done' | 'archived' | 'failed' | 'missed'
   - `GoalSource` — 'manual' | 'ai' | 'system'
   - `TargetType` — 'time' | 'completion' | 'external' | 'habit' | 'cross_feature'
   - `TrackingMode` — 'system' | 'manual' | 'hybrid'
   - `CompletionLogic` — { lateAllowed: boolean; gracePeriodMinutes: number; partialCredit: boolean; streakOnMiss: 'reset' | 'continue' | 'pause' }
   - `Goal` interface with ALL fields from all 3 current definitions, plus new ones
   - `LongTermGoal` interface (unified)
2. Update `src/components/dashboard/types.ts` to re-export from `src/types/goals.ts`
3. Update `src/components/ai/types.ts` to re-export from `src/types/goals.ts`
4. Update `src/services/GoalStore.ts` to use canonical types
5. Update all import sites (grep for old import paths)

**Edge cases:**

     - `habit`: cadence selector (fixed/rolling/flexible) + target days

### Engineering C — Completion Logic & Missed Goal Handling
**Goal:** Implement configurable completion rules and a recovery flow for missed goals.

**Implementation:**
1. Add DB columns to `goals` table via guarded ALTER:
   - `completion_config TEXT` (JSON: `{ lateAllowed, gracePeriodMinutes, partialCredit, streakOnMiss }`)
   - `tracking_mode TEXT DEFAULT 'manual'` ('system' | 'manual' | 'hybrid')
   - `cadence_config TEXT` (JSON: `{ type, fixedDays, rollingTarget, flexibleWindowDays }`)
   - `cross_feature_link TEXT` (JSON: `{ feature, entityId, label }`)
   - `external_activity_id INTEGER` (FK to external_activities.id)
2. Update `save-goal` IPC to persist new fields
3. Update `get-goals-batch` / `get-goal` IPC to return new fields
4. Build `GoalCompletionEngine` (renderer-side utility):
   - Evaluates whether a goal is completed based on its completion logic
   - Handles late completion (within grace period)
   - Computes partial credit (e.g., 70% of target = 70% complete)
   - Determines streak impact on miss
5. Build `MissedGoalRecovery` UI:
   - When a goal is marked as missed (past date, not completed), show recovery options:
     - Reschedule to today
     - Mark as completed anyway (with late flag)
     - Dismiss (accept the miss)
     - Ask AI for suggestion
   - Shows in a non-intrusive banner or section on the GoalsPage
6. Update `GoalCard` to show:
   - Tracking mode badge (system/manual/hybrid)
   - Completion logic summary (e.g., "Late OK, 1-day grace")
   - Missed status with recovery actions

**Edge cases:**
- Grace period must be computed in LOCAL time, not UTC
- Partial credit must not exceed 100%
- Streak reset must cascade to child goals (if parent LTG streak is reset)
- Missed goal recovery must not allow marking a goal as completed if tracking mode is 'system' and no data exists

### Engineering D — Cross-Feature Integration Layer
**Goal:** Connect goals to every data source in the app so goals can track progress from Learn, Finance, External, IDE, and Focus.

**Implementation:**
1. New IPC: `goal:get-cross-feature-progress`
   - Takes goal ID, reads `cross_feature_link` from DB
   - Routes to the appropriate feature's data:
     - Learn: query `learn_nodes` / `learn_progress` for topic completion
     - Finance: query `finance_goals` for savings progress
     - External: query `external_sessions` for activity time
     - IDE: query `projects` / `code_activity` for project activity
     - Focus: query `deep_focus_sessions` / `focus_group_usage` for focus time
   - Returns `{ progress: number; target: number; percentComplete: number; details: string }`
2. New IPC: `goal:get-system-tracked-progress`
   - For goals with `tracking_mode = 'system'` or `'hybrid'`
   - Combines all available data sources to compute progress
   - Uses `matchCategory` for time-based goals (existing logic)
   - Uses `external_activity_id` for external activity goals (existing logic)
   - Uses `cross_feature_link` for cross-feature goals (new logic)
3. Update `get-daily-goal-progress` to include cross-feature progress
4. Update `useGoalProgress` hook to call new IPC endpoints
5. Update `GoalCard` progress bar to show cross-feature progress source

**Edge cases:**
- Cross-feature link must handle deleted entities gracefully (show "Link broken" state)
- System-tracked progress must not double-count (e.g., focus time that also counts as app category time)
- Hybrid mode must merge system-tracked + manual check-in progress

### Engineering E — AI Dynamic Goal Monitor
**Goal:** AI periodically evaluates goal health and proposes adjustments; user approves before changes take effect.

**Implementation:**
1. New IPC: `goal:ai-monitor`
   - Triggered manually (button in GoalsPage) or on app launch (check if last monitor > 24h ago)
   - Gathers: all active goals, their progress over last 7 days, completion rates, streak data
   - Sends to AI with system prompt:
     ```
     You are a goal coach. Analyze the user's goals and progress data.
     For each goal that needs attention, propose ONE specific adjustment.
     Return JSON: { proposals: [{ goalId, action: 'reschedule'|'adjust_target'|'split'|'retire'|'celebrate', reason: string, newConfig?: Partial<Goal> }] }
     Rules:
     - Never auto-apply changes. All proposals require user approval.
     - Be specific: "Move deadline from Aug 30 to Sep 2" not "consider extending deadline"
     - Celebrate wins: if a goal is completed early or ahead of schedule, say so
     - If a goal has been missed 3+ times, suggest splitting into smaller goals
     - If a goal's target is consistently exceeded, suggest increasing it
     ```
   - Returns proposals array
2. New IPC: `goal:ai-apply-proposal`
   - Takes proposal ID + goal ID + approved config changes
   - Applies the changes to the goal via `save-goal`
   - Logs the AI adjustment as a context brain episode
3. UI: `GoalAICoach` component in GoalsPage
   - Shows "AI Health Check" button
   - When triggered, shows loading state, then displays proposals as cards
   - Each proposal has: goal title, action, reason, "Apply" / "Dismiss" buttons
   - Applied proposals update the goal and show confirmation
4. New IPC: `goal:ai-generate-from-language`
   - Takes natural language input (e.g., "I want to practice piano 3 times a week for 30 minutes")
   - AI parses into a structured Goal config
   - Returns the parsed goal for user review before saving
   - System prompt includes all available goal fields and their constraints

**Edge cases:**
- AI monitor must handle goals with zero progress data gracefully (suggest first steps)
- Proposals must not conflict with each other (e.g., can't reschedule AND split the same goal)
- Language parser must validate that referenced features/activities exist in the system
- Rate limit: max 1 AI monitor call per 6 hours (prevent API spam)

### Engineering F — Habit Tracker Integration
**Goal:** Surface the existing `is_habit`/`cadence`/`weekly_target_days` DB columns in a dedicated habit tracking UI.

**Implementation:**
1. Build `HabitTracker` component:
   - Shows habits in a weekly grid (7 columns, one per day)
   - Each row = one habit with: name, category, completion dots per day
   - Streak counter per habit (consecutive days completed)
   - "Today" column highlighted
   - Click a dot to toggle completion
2. Wire into GoalsPage as a tab or section (alongside "Goals" and "Long-term")
3. Wire into GoldPage's covenant section
4. Update CriteriaBuilder to support habit creation:
   - When `isHabit = true`, show cadence selector (daily/weekly)
   - For weekly: show day-of-week checkboxes
   - Hide time-based target config (habits are completion-based)
5. New IPC: `goal:get-habits`
   - Returns all goals where `is_habit = 1`, grouped by cadence
   - Includes per-day completion status for the current week
6. New IPC: `goal:toggle-habit-day`
   - Toggles completion for a specific habit on a specific date
   - Updates streak calculation

**Edge cases:**
- Habit completion on a day with no tracking data must still be allowed (manual check-in)
- Weekly habits with `weekly_target_days` must show progress toward the target (e.g., "3 of 5 days")
- Streak calculation must account for the habit's cadence (daily = consecutive days, weekly = consecutive weeks)
