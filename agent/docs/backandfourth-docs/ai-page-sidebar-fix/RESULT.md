# RESULT.md — Root Cause Analysis & Fix Specification

## 1. Root Cause Analysis

After three rounds of iterative investigation, systematically ruling out JavaScript event hijacking, invisible modal overlays, and React state issues, the root cause has been identified as a **Chromium Compositor Layer/Hit-Testing Conflict** triggered by the `will-change` CSS property.

### The Chain of Events:
1. **The Trigger:** The `/ai` page renders the `CanvasGrid` component, which applies the CSS class `.dk-canvas-grid-layer`. This class contains the rule `will-change: transform;`.
2. **The Compositor Promotion:** In Electron (which runs Chromium), applying `will-change: transform` forces the browser to promote this element (and its ancestors, like the `flex-1` main content area) to a new GPU compositor layer to optimize rendering performance.
3. **The Overlap:** Because the main content area (`flex-1`) comes *after* the sidebar in the DOM order, the compositor places this newly promoted layer above the sidebar's layer. Even though the elements do not visually overlap horizontally, the compositor layer's bounding box covers the entire viewport width. 
4. **The Silent Blockade:** The compositor intercepts all `pointerdown` / `click` events in this bounding box for hit-testing. Because the sidebar's previous `z-20` was insufficient to elevate it above this dynamically generated compositor layer in the stacking context, clicks on the sidebar were silently swallowed by the main content's compositor layer. No JavaScript `onClick` handler ever fired, which is why there were no console logs or route changes.

### Why Only the `/ai` Page?
The `/ai` page is the only route in the application that utilizes a canvas with `will-change: transform` combined with continuous panning/zooming transforms. Other pages use standard `overflow-auto` or static flexbox layouts, which do not trigger this aggressive compositor layer promotion.

## 2. Implementation Plan

**File:** `src/App.tsx` (application shell layout)

**Change:**
Locate the sidebar container `motion.div` (line 2331 in `src/App.tsx`). Update the `className` to explicitly enforce a high z-index, ensuring the sidebar's compositor layer remains strictly above the main content area.

*Before:*
```tsx
<motion.div
  className="border-r border-zinc-800 flex flex-col h-full glass overflow-hidden z-20"
  // ...
>
```

*After:*
```tsx
<motion.div
  className="border-r border-zinc-800 flex flex-col h-full glass overflow-hidden z-[100]"
  // ...
>
```

**Secondary Fix:**
**File:** `src/pages/TerminalPage.tsx` (line 1933)

Add cleanup for `__workspaceHasUnsavedChanges` on unmount to prevent stale workspace guard from blocking navigation on other pages.

*Before:*
```tsx
useEffect(() => {
  (window as any).__workspaceHasUnsavedChanges = hasUnsavedChanges;
}, [hasUnsavedChanges]);
```

*After:*
```tsx
useEffect(() => {
  (window as any).__workspaceHasUnsavedChanges = hasUnsavedChanges;
  return () => { (window as any).__workspaceHasUnsavedChanges = false; };
}, [hasUnsavedChanges]);
```

**Why `z-[100]`?**
Tailwind's arbitrary value `z-[100]` is high enough to trump any `z-50` (toasts), `z-66` (modals), and the implicit compositor layers generated by `will-change` within the main content area, without breaking global modals that might use `z-[9999]`.

## 3. Verification Steps

1. **Start the application** and navigate to the AI Assistant page (`/ai`).
2. **Interact with the Canvas:** Pan and zoom the canvas to ensure the compositor layers are actively generated and promoted.
3. **Test Sidebar Navigation:** Click every item in the sidebar (Dashboard, Activity, IDE, Settings, etc.).
   - *Expected Result:* The application should route to the selected page immediately. No clicks should be swallowed.
4. **Return and Retest:** Navigate back to `/ai` and repeat the process to ensure stability across multiple mounts/unmounts of the canvas component.
5. **Check Responsive States:** Collapse and expand the sidebar using the toggle button while on the `/ai` page to ensure the z-index does not visually clip the sidebar animations.
