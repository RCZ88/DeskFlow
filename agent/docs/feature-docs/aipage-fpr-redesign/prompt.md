## Engineering Task — Data Processing & Pipeline

Design the data-processing layer that feeds the visual overhaul:

1. **Mode computation** — AiPage currently computes `mode` from goal completion + time-of-day. Design a clean pipeline to expose this to all three sections consistently (morning → in-progress → review). Include how the weekly `getGoalsBatch` data feeds the "unfinishedCount" / "completedThisWeek" pills in SectionHead right slots.

2. **Empty state inference** — Each card has distinct empty-state logic:
   - DailyPlanCard: no goals + no suggestions → show "Plan your day" CTA with Suggest button
   - MyPlanCard: planning.md missing or empty → default template injection
   - LongTermPlanCard: no long-term goals → manual add form OR bulk import CTA
   - TopicDigestCard: no topics → reason from settings + Refresh CTA
   - GoalHistoryCard: no goals in last 7 days → empty Calendar state
   
   Design a unified `ViewState` wiring so each card's StateShell transitions correctly between loading → empty → error → populated.

3. **Cross-section data sharing** — `planGoals` (from MyPlanCard's planning.md) feeds into DailyPlanCard's "From your plan" section. `goals` array is shared across Focus and Reflect (GoalHistoryCard loads the same data series). Design the flow — no new IPC channels, reuse existing `readPlanningMd()` and `getGoals(date)`.

4. **Optimistic UI** — `onToggle`, `onAccept`, `onDismiss`, `onFeedback` are fire-and-forget. Design visual feedback patterns that work with this: instant local update + fade-to-confirm + error rollback. 400ms max roundtrip perceived latency.

## Design Task — High-Fidelity Visual Specs

Each card must be redesigned to match the Dark Glass / dev-tool aesthetic established in RESULT_NEW.md. For **every** card, specify:

1. **Card wrapper** — GlassCard with `!p-0 overflow-hidden` or standard `p-5`? Accent bar (color, which side)? `whileHover={{y:-2}}`?

2. **Header area** — icon (lucide, reactbits) size, title text style, badge/pill styles (SectionHead or inline), optional provider badge, action buttons (IconButton). Exact token values.

3. **Content regions** — list items, accordion sections, metric displays, progress indicators, inline editors. All must use:
   - `p-3` / `p-4` for list items, `p-5` max for cards
   - `ring-1 ring-zinc-800/60` for dividers/separation
   - `rounded-xl` max radius
   - Category badges: `bg-{color}-500/10 text-{color}-300 ring-{color}-500/20` with colored dot
   - Text hierarchy: `text-zinc-100` primary, `text-zinc-400` secondary, `text-zinc-500` muted, `text-[11px]` metadata

4. **Interactive states** — hover (y:-1, ring shift), focus (ring-2 pink/60), pressed (scale:0.98), disabled (opacity-40 + no-pointer). Exact token mappings. 150ms transitions.

5. **Progress visualization** — DailyPlanCard SVG ring (current) vs any alternative. LongTermPlanCard's section header shows "N active · M done". MetricCard count-up animation (reactbits CountUp or custom).

6. **Section headers** — SectionHead accent bar + title + description + right pill slot. Ensure all three sections have consistent spacing (`space-y-6` between sections, `space-y-4` within).

7. **Color palette per section**:
   - **Focus** → pink accent (cartesian: pink-500 for interactive, pink-400/30 for backgrounds)
   - **Plan** → emerald accent (emerald-500 interactive, emerald-400/30 backgrounds)
   - **Reflect** → amber accent (amber-500 interactive, amber-400/30 backgrounds)
   - Category colors remain: work(violet), personal(cyan), health(emerald), learning(amber), finance(rose), relationships(pink)

8. **Animation choreography** — MOTION tokens only:
   - Section entrance: stagger children (0.05), each child y:6→0 + opacity:0→1, 250ms, ease [0.16,1,0.3,1]
   - Card hover: y:-2, 150ms
   - List item hover: y:-1, 150ms
   - Accordion expand: height auto, 250ms, easeInOut
   - Toggle check: scale bounce (1→1.15→1), 250ms total, cubic-bezier
   - Mode transition (morning→in-progress→review): crossfade 400ms
   - No spring, no parallax, no particles
   - `prefers-reduced-motion`: collapse all to 0s duration

## UX Task — Interaction Design

For every card and every interactive element, specify:

1. **Click/tap targets** — minimum 44×44px hit area (IconButton uses 44px via `-m-1.5` padding). Never break this.

2. **Accordion behavior** — TopicDigestCard (per topic), GoalHistoryCard (per day), DailyPlanCard (completed section), LongTermPlanCard (completed goals). All must:
   - Chevron rotate on open (180°), 250ms ease
   - Content expand with `AnimatePresence` + `motion.div layout`
   - Persist open/closed state locally (useState, not localStorage)

3. **Inline editing** — MyPlanCard's textarea (edit/preview toggle) and DailyPlanCard's feedback input must show unsaved indicator, debounce save, confirm save success. Error revert without data loss.

4. **AI generation states** — LongTermPlanCard bulk mode (analyzing → parsed preview → import), DailyPlanCard suggestions (suggesting → accept/dismiss), TopicDigestCard (loading → refresh). All must show StateShell-compatible loading with progress narrative text.

5. **Semantic feedback** — Toast-like confirmation for saves, imports, toggles. Use existing patterns from RESULT_NEW.md (emerald banner with checkmark, auto-dismiss after 3s). Error states must never clear user input — show inline under the affected control.

6. **Keyboard navigation** — Tab order follows visual order. Enter to submit/save. Escape to close accordion or cancel edit. Focus ring `focus-visible:ring-2 focus-visible:ring-pink-500/60 focus-visible:outline-none`.

## Constraints (Hard Invariants)

1. **Zero feature removal** — every prop, button, state, data flow, and interaction described in the context bundle must exist in the output. Additive visual overhaul only.
2. **No new IPC channels** — use only the 14 channels documented in the bundle. If a feature needs data the existing channels don't provide, note the gap — do not create a new channel.
3. **No new npm packages** — use only existing dependencies: React 19, framer-motion 12, lucide-react, tailwind v4, shadcn/ui components. Magic UI / ReactBits components permitted via MCP (must reskin to DeskFlow tokens).
4. **Tailwind v4 only** — no arbitrary CSS classes, no style prop for layout. All tokens map to tailwind classes.
5. **No box-shadow** — use ring-1 borders for card boundaries. `bg-zinc-900/40` + `ring-1 ring-zinc-800/60` as base card visual.
6. **rounded-xl max** — no `rounded-2xl` or `rounded-3xl`. `rounded-xl` is the maximum radius anywhere.
7. **p-5 max padding** — cards max p-5. List items p-3 or p-4. Section margins use tailwind spacing scale.
8. **transform + opacity only for animation** — never animate width, height, or layout properties. Use `layoutId` or `AnimatePresence` for enter/exit.
9. **All localStorage access wrapped in try/catch**.
10. **CRLF line endings** — do not mass-reformat files.
11. **6 design skills are mandatory** — after you produce the spec, verify every decision passes all 6:
    - **motion-alive**: L2 micro-interactions, single ambient accent, 150/250/400ms, no spring
    - **impeccable**: 8px grid, type scale, Geist/JetBrains Mono, accent discipline
    - **humancentred-UIUX**: 4-state coverage, plain copy, visual hierarchy, forgiveness, accessibility
    - **ui-ux-pro-max**: dark chrome, monospace, high density, pink accent
    - **frontend-design**: progressive disclosure, glass structure, no shadow, no width/height animation
    - **frontend-external-infra**: pull from MCP (shadcn, Magic UI, Lucide, ReactBits), re-skin to DeskFlow tokens
12. **Confirmed-invariant PTY event order is sacred** (not applicable here, listed for completeness).
